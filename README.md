# Pickaxe Drop и Мины — Telegram Mini App

Две пиксельные игры с общим профилем Telegram и балансом в ₽. При входе доступно **одно бесплатное колесо** с наградами 500, 1000, 3000 и 5000 ₽. Награда определяется сервером и зачисляется один раз. Серверная логика обеих игр находится в `main.py`, данные сохраняются в SQLite.

## Запуск

Требуется Python 3.10+; сторонних библиотек для запуска нет. На Bothost добавлять переменные вручную не требуется: платформа передаёт токен подключённого Telegram-бота и домен, а приложение автоматически определяет настройки.

Выполните `python main.py`. Сервер сам устанавливает webhook и кнопку «Играть» в меню бота. При временной недоступности Telegram настройка повторяется в фоне; сайт продолжает работать. Отправьте боту `/start`: бот отправит приветствие с баннером, выделенным текстом и двумя custom emoji. Зелёная инлайн-кнопка «⚒️Играть» откроет Mini App; кнопка «💬 Поддержка» ведёт на [@Game_shaxter_support](https://t.me/Game_shaxter_support). Контакт задаётся через `SUPPORT_USERNAME` в начале `main.py`; он также доступен по команде `/support`.

Баннер хранится в `static/assets/welcome-banner.png` и отдаётся сервером по `/static/assets/welcome-banner.png`. Для custom emoji владелец бота должен иметь Telegram Premium, либо у бота должен быть приобретён дополнительный username на Fragment. При отклонении custom emoji Telegram приветствие отправляется с обычными эмодзи, сохраняя баннер, выделение и кнопки. [Форматирование Telegram Bot API](https://core.telegram.org/bots/api#html-style).

## Bothost

1. При создании Telegram-бота на Bothost укажите его токен от @BotFather в обычном поле подключения бота.
2. Подключите этот репозиторий, выберите ветку **`main`** и главный файл **`main.py`**. Сайт и бот работают одним Python-сервером.
3. В дополнительных настройках включите **«Использовать домен»**; внутренний порт приложения — **3000**.
4. Запустите или повторно разверните приложение. Раздел «Переменные окружения» заполнять не нужно. Для уже созданного бота достаточно обновить приложение из репозитория.
5. Дождитесь строки `Telegram webhook and menu button registered` в логах, затем отправьте боту `/start` и откройте Mini App кнопкой **«⚒️Играть»**.

Приложение использует автоматически предоставленные Bothost `BOT_TOKEN` (также поддерживаются `TELEGRAM_BOT_TOKEN` и `API_TOKEN`) и `DOMAIN`. При отсутствии `DOMAIN` полный идентификатор платформы вида `bot_…` из `BOT_ID` преобразуется в стандартный адрес `https://bot-….bothost.tech`. Адрес из HTTP-заголовков посетителя для настройки бота не используется.

Секрет webhook вычисляется из токена бота и сохраняет значение после перезапуска; вручную генерировать его не требуется. Порт по умолчанию — `3000`, база создаётся автоматически в `data/pickaxe.sqlite3`; в комплектном Dockerfile используется `/data/pickaxe.sqlite3`.

Главная страница открывается по `/`, состояние сервера — по `/health`, webhook принимает сообщения и нажатия по `/telegram/webhook`. В `/health` поле `telegram_ready` становится `true` после настройки webhook и кнопки. Если хостинг ещё не передал токен или домен, в логах будет подсказка проверить подключение бота и опцию домена. Если Telegram отвергает токен, исправьте токен в настройках подключения бота на Bothost.

Не нужна отдельная публикация frontend: `main.py` отдаёт страницы, файлы, API игр и обрабатывает Telegram. В репозитории есть готовый `static/index.html`; для запуска сборка не требуется. Для собственной контейнерной сборки предусмотрен `Dockerfile`.

Документация: [веб-приложения и домены](https://bothost.ru/docs/web-apps-domains), [домены и порты](https://bothost.ru/docs/domains-and-ports).

## Необязательные настройки для других хостингов

На Bothost эти значения определяются автоматически. На другом хостинге или при особой конфигурации их можно переопределить:

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен подключённого Telegram-бота. |
| `WEBAPP_URL` | Явный публичный HTTPS-адрес вместо домена платформы. |
| `TELEGRAM_WEBHOOK_SECRET` | Собственный секрет вместо автоматически вычисленного. |
| `DATABASE_PATH` | Путь существующей SQLite-базы или постоянного диска. |
| `PORT` | Внутренний порт сервера вместо `3000`; сервер слушает `0.0.0.0`. |
| `REGISTER_WEBHOOK` | `0` — отключить автоматическую регистрацию; по умолчанию она включена. |

Файл `.env` автоматически не загружается. Команда `python main.py set-webhook` повторно настраивает Telegram с теми же автоматически определёнными настройками.

Без постоянного диска база исчезнет при пересоздании контейнера. Существующая база обновляется автоматически: балансы и история сохраняются при добавлении «Мин».

Запросы приложения требуют корректную подпись `Telegram.WebApp.initData` и свежий `auth_date`.

`static/index.html` содержит встроенные стили, JavaScript, кириллический шрифт, изображения и звуки. Постоянный баланс и авторизация работают через `main.py`. После изменения исходников выполните `python build_index.py`.

## Pickaxe Drop

- Ставка вводится вручную, от 1 ₽ и в пределах доступного баланса; поддерживаются копейки. Кнопки «−» и «+» быстро меняют сумму, **MAX** выбирает весь баланс. Суммы больше 500 ₽ доступны в обеих играх.
- Сервер выдаёт кирку перед раундом: каменная — **100 HP, 50%**; железная — **150 HP, 35%**; алмазная — **250 HP, 15%**.
- Кирки прокручиваются внутри каменного портала, замедляются, останавливаются на серверном результате и вылетают в шахту.
- Камень и TNT уменьшают прочность. Сердце восстанавливает её до максимума выпавшего вида. Предел шахты — 96 блоков.
- Руда увеличивает выигрыш. Усилители повышают награду следующих находок до ×4. Платного бонуса ×2 нет.
- Добыча и бонусы входят в результат раунда. Сервер сохраняет весь раунд до анимации. Повтор `request_id` не списывает ставку повторно.

`static/physics.js` рассчитывает гравитацию, вращение, отскоки, боковые стенки и TNT с шагом 1/120 секунды. Блок исчезает при контакте; в этот момент обновляются прочность и добыча. Положение и скорость при вылете совпадают с первым кадром физики. Камера размещает кирку над кнопками, включая короткие экраны. Серверный `physics_seed` обеспечивает одинаковое воспроизведение при разных частотах кадров.

## Мины

- Поле **5×5**, выбор **3, 5 или 7 мин**, ручной ввод суммы и MAX.
- Ставка списывается один раз при старте. Положение мин определяет сервер и скрывает до завершения игры.
- Безопасная клетка показывает изумруд и увеличивает награду. После первой находки можно забрать её или продолжить.
- Открытие всех безопасных клеток автоматически зачисляет награду.
- Награду рассчитывает сервер. Суммы хранятся в целых копейках.
- Незавершённый раунд восстанавливается после перезагрузки. Повторные открытия и запросы забрать награду не платят повторно.
- Пока активны «Мины», сервер не позволяет начать Pickaxe Drop. Обе игры отображаются в общей истории.

API: `GET /api/mines`, `POST /api/mines/start`, `POST /api/mines/reveal`, `POST /api/mines/cashout`. Параметр `round_id` в `GET /api/mines` восстанавливает итог после потери ответа. Каждый раунд доступен только своему Telegram-пользователю. Изменения баланса проходят через SQLite-транзакции.

## Интерфейс и ресурсы

Меню сохраняет чёрно-лаймовый стиль референса: капсула профиля, небольшие карточки игр и нижние вкладки. Баннеры листаются свайпом, кнопками-точками и стрелками клавиатуры. Предоставленные изображения «Мин» лежат в `static/assets/mines-banner.png` и `mines-card.png` без изменений; баннер отображается целиком.

На экране Кирки нет тёмного градиента или затемнения при выпадении. Баланс и выигрыш разделены на две колонки, ставка — в отдельной строке; длинные суммы подстраивают размер шрифта. Обе игры используют светлые панели и ровную пиксельную графику. Кирки, поле, изумруды и бомбы рисуются Canvas.

Полный **Inter Variable с кириллицей** взят из [Otongift](https://github.com/malojloh69-source/Otongift) и применяется ко всем надписям, цифрам и кнопкам. Сборка проверяет целостность WOFF2. Лицензия — `Inter-LICENSE.txt` (SIL Open Font License).

Звуки запуска, ударов, находок, взрыва и результата — короткие фрагменты предоставленной записи в `static/assets/sounds/`. Они встроены в HTML и запускаются после взаимодействия пользователя. Обе игры используют общую настройку звука, сохраняемую на устройстве. При скрытии приложения эффекты и анимация Кирки приостанавливаются. Настройка «Уменьшение движения» отключает анимации интерфейса.

Верхняя лента круглых карточек и большая панель выбора кирки убраны. Правила доступны по кнопке «Как играть». Скриншоты и исходное видео в архив проекта не входят.

## Менеджер: пополнение и вывод

В самом начале `main.py` задайте:

```python
MANAGER_USERNAME = "@your_manager"
```

Допустим username с @ или без него. После изменения перезапустите сервер. Пока username не задан, денежные заявки не создаются.

Кнопка «+» в меню открывает панель пополнения на половину экрана. В профиле доступны «Пополнение» и «Вывод». Сначала пользователь вводит сумму, затем видит вторую панель с суммой, номером заявки и кнопкой перехода к менеджеру. Заявку можно скопировать и отправить менеджеру самостоятельно.

Пополнение не зачисляется до подтверждения. При выводе сумма резервируется; её нельзя потратить в игре. Отмена вывода возвращает резерв на баланс. Существующие балансы при обновлении сохраняются; новым профилям стартовую сумму выдаёт колесо.

Менеджер управляет заявками в личном чате с ботом:

| Команда | Действие |
| --- | --- |
| `/requests` | Показать заявки на рассмотрении. |
| `/complete НОМЕР` | Подтвердить заявку после фактической оплаты или выплаты. |
| `/cancel НОМЕР` | Отменить заявку; для вывода вернуть резерв. |

Команды доступны менеджеру из `MANAGER_USERNAME` и вошедшим администраторам, в личном чате. Webhook защищён автоматически вычисленным секретом. Повторное подтверждение или отмена не изменяет баланс повторно. Перевод средств менеджер проводит вручную; приложение хранит заявки и обновляет баланс после подтверждения.

## Панель администратора в чате

Отправьте боту **`/ClezzyKryt`** в личном чате. Каждый, кто знает этот код, получает доступ к панели. Код задаётся в `ADMIN_ACCESS_CODE` в начале `main.py`. После входа доступ сохраняется за Telegram ID, даже после перезапуска. Команда **`/admin`** открывает панель повторно.

- **Заявки**: пополнения и выводы, просмотр ожидающих, подтверждённых и отменённых; подтверждение и отмена кнопками.
- **Пользователи**: список с балансами, поиск по ID, @username или имени, карточка и последние раунды.
- **Изменение баланса**: ввод новой суммы и отдельная кнопка подтверждения. Активный раунд «Мин» нужно завершить перед изменением.
- **Статистика**: пользователи, общий баланс, раунды, поступления, выплаты и ожидающие заявки.
- **Журнал действий**: кто подтвердил или отменил заявку и кто изменил баланс.
- **Выход**: прекращает доступ; для повторного входа снова нужен код.

Панель работает только в личном чате. Чужие и пересланные кнопки не открывают доступ; денежные действия сохраняются атомарно и не применяются повторно.

Те же действия доступны оператору на сервере с тем же `DATABASE_PATH`:

```bash
python main.py wallet-list
python main.py wallet-complete НОМЕР
python main.py wallet-cancel НОМЕР
```

Сборка интерфейса: `python build_index.py`. Игровые расчёты, колесо, денежные заявки и команды менеджера находятся в `main.py`.
